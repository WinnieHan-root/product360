# 20261026 效果图解读与前端视觉优化结论

> 目的：记录 `docs/20261026-*.jpg` 当前已识别的效果图内容、视觉特征，以及对 `apps/web` 现有商品中心前端的直接启发。
>
> 说明：本文档仅沉淀设计分析与优化结论，**不代表当前代码已实现**。

## 1. 已识别效果图内容

### 1.1 `docs/20261026-192054.jpg`

这是一个**方案总览 / 原型首页**，不是单个商品的业务详情页。

#### 页面内容
- 顶部标题：`商品多模态数据库（Product Intelligence DB）原型`
- 顶部说明区分为四块：
  - 产品定位
  - 核心设计目标
  - 关键用户案例
  - 数据覆盖范围
- 主体为 5 个并列能力模块卡片：
  1. 商品 360° 概览
  2. 全渠道信息
  3. 商品素材管理
  4. 外部信息分析
  5. AI 问答助手

#### 页面特征
- 首屏信息量非常高，但通过**分栏 + 卡片化**保持秩序。
- 每个模块卡片都不是简单标题，而是内嵌：
  - 小指标
  - 小图表
  - 小表格
  - 小列表
- 更像“能力展示型 dashboard”，强调一眼看全局。

#### 对现有项目的启发
- 首屏不必过分留白，关键是**模块边界清晰**。
- 一个页面中可以同时容纳：摘要、图表、表格、列表，而不是只能选一种。
- 如果要提升信息密度，应优先采用**多列并排**，而不是继续纵向堆叠。

### 1.2 `docs/20261026-192100.jpg`

这是一个**商品主数据详情页**，偏“商品档案 / 主数据治理”视角。

#### 页面内容
- 左侧是完整导航，当前高亮在：`主数据 / 公司商品主数据`
- 顶部头部区域包含：
  - 商品大图
  - 商品名称：`M9 穿戴式吸奶器，24mm, Cozy Red, 2件套`
  - 一组核心标签：SPU、SKU、型号、品牌、类目、规格等
  - 右侧摘要卡：
    - 主数据完整度（92%）
    - 缺失字段提醒
    - 审核状态（已通过）
- 中部内容区由多块卡片并排组成：
  - 商品基本信息
  - 生命周期与状态
  - 变体列表
  - 包装与配件信息
  - 属性表（核心属性）
  - 关联条码与平台 ID
  - 主数据变更记录

#### 页面特征
- 这是典型的**高密度 B 端详情面板**。
- 第一屏已经同时出现：
  - 商品识别信息
  - 质量状态
  - 审核状态
  - 变体摘要
  - 包装信息
  - 属性信息
- 不是“长文档阅读流”，而是“信息面板 + 工作台”。

#### 对现有项目的启发
- `ProductLayout` 顶部头部应进一步强化，而不是只承担标题作用。
- `OverviewPage` 不应只是字段平铺，应改成**基础信息 + 状态信息 + 包装摘要 + 变体摘要**的首屏矩阵。
- “完整度 / 缺失提醒 / 状态”类内容非常适合做成 summary 卡或提示卡，而不是隐藏在表格后。

## 2. 这几张效果图的共同特征

### 2.1 首屏信息非常满
共同特点不是“留白很多”，而是：
- 一打开就有很多信息
- 但通过网格、卡片、分栏保证不乱

设计结论：
> 要接近这些效果图，现有前端必须从“滚动阅读页”向“首屏信息面板”转变。

### 2.2 强调摘要 + 明细 + 建议的组合
这些效果图都不是单纯的：
- 只有表格，或
- 只有图表，或
- 只有字段卡

而是同时组合：
- summary 卡
- 小图表 / 大图表
- 表格 / 矩阵
- 问题提醒
- 行动建议
- 快捷入口

设计结论：
> 页面要更像“业务工作台”，而不是“字段结果页”。

### 2.3 横向布局使用很多
这些图都大量使用：
- 多列并排
- 左中右分区
- 顶部摘要带
- 中部主视图 + 右侧辅助区

设计结论：
> 如果继续采用大段纵向堆叠，首屏信息密度就很难接近目标效果。

### 2.4 图表和进度条参与度高
效果图中很多业务信息不是靠纯文字表达，而是通过：
- 进度条
- 小型趋势图
- 指标卡
- 状态圈图
- 分布图

设计结论：
> 现有前端如果想更接近样例图，需要让图表成为页面的核心视觉元素之一，而不只是底部附属模块。

### 2.5 强烈的业务感
这些页面不像通用后台模板，而像明确服务于：
- 商品主数据治理
- 渠道运营
- 内容治理
- 外部口碑洞察

设计结论：
> 现有页面需要强化“业务语义可视化”，例如覆盖度、完整度、渠道数、评论数、趋势、异常提醒等。

## 3. 对现有四个页面的直接映射建议

> 目标不是逐像素复刻，而是把这几张效果图的设计方法迁移到当前第一期只读商品中心。

### 3.1 Catalog（商品列表页）

#### 当前问题
- 首屏主要是筛选 + 表格，信息量偏少。
- 用户需要往下滚动，才能形成“系统整体情况”的感觉。

#### 建议迁移方向
参考 `20261026-192054.jpg` 的“总览型 dashboard”思路：
- 在列表页表格上方加入一排轻量 summary 卡，例如：
  - 商品总数
  - 有明细商品数
  - 覆盖度 4/4 商品数
  - 近 30 天有销量商品数
  - 有口碑商品数
- 加一个轻量概览区，用于展示：
  - 商品状态分布
  - 覆盖度分布
  - 当前权限范围 / 当前筛选结果摘要
- 提升表格首列承载量：
  - 商品图
  - 中文名 / 英文名 / SPU
  - 等级 / 状态 / 品牌 / 类目次信息

#### 设计原则
- 列表页不能只是“表格页”，而应成为“商品盘点首页”。

---

### 3.2 Overview（商品概览页）

#### 当前问题
- 已有基础信息、标签、包装、变体，但整体仍偏字段展示。
- 首屏虽然完整，但还不够“面板化”。

#### 建议迁移方向
参考 `20261026-192100.jpg` 的“主数据详情面板”思路：
- 强化 `ProductLayout` 顶部头卡：
  - 商品图
  - 中文名 / 英文名 / SPU
  - 品牌 / 类目 / 等级 / 状态
  - 数据来源 / 更新日期
- 在头部右侧加入只读型 summary 卡：
  - 数据完整度（可由 coverage 派生）
  - 缺失字段提醒（按 `empty` / `not_connected` 汇总）
  - 生命周期状态 / 上架状态
- 把概览页首屏改造成 2~3 列矩阵：
  - 左：基础信息
  - 中：标签信息
  - 右：包装摘要
- 在完整变体表前增加“变体摘要条”：
  - 变体总数
  - 有渠道编码的变体数
  - 未接入编码说明

#### 设计原则
- 概览页不是字段清单，而应是“商品档案面板”。

---

### 3.3 Channels（全渠道页）

#### 当前问题
- 已有 summary 卡、表格、趋势图，但还是偏“标准管理后台”。
- 首屏还可以承载更多经营判断信息。

#### 建议迁移方向
参考 `20261026-192104.jpg` 的“渠道经营看板”思路：
- 保留并强化顶部 summary 卡：
  - 渠道数
  - 近 N 天销量
  - 近 N 天销售额
  - 在库
  - 在途
- 在 summary 卡下方改成“左主右辅”结构：
  - 左侧：趋势图 / 渠道贡献图 / 核心对比区
  - 右侧：问题与预警、推荐下一步、渠道在线概览
- 研究把当前普通表格升级为更强的渠道对比视图：
  - 渠道列信息层级更强
  - 价格 / 库存 / 销量 / 状态更适合横向扫读
- 底部可增加：
  - 渠道变化时间线
  - 差异提示
  - 内容完整度 / 覆盖度构成

#### 设计原则
- 渠道页不应只是“渠道明细表”，而应首先回答“这个商品的渠道经营状态怎样”。

---

### 3.4 External（外部信息页）

#### 当前问题
- 结构已对齐契约，但视觉上仍可以更像“口碑洞察面板”。
- 图表和分布可视化还不够强。

#### 建议迁移方向
参考以上效果图中“摘要 + 图表 + 主题 + 辅助区”的组合方式：
- 顶部增加更强的外部口碑 summary 卡：
  - 星级均值
  - 评论数
  - 工单数
  - 竞品数 / 竞品是否有数据
- 首屏主区域改成两列：
  - 左：五档情感分布 + 评分/评论趋势
  - 右：评论主题 + 工单主题 + 说明提示
- 工单 note 建议做成独立提示条，而不是弱文案。
- 竞品区建议增强空态设计；有数据时可进一步增加对比图，而不只是一张表。

#### 设计原则
- 外部页的目标不是“列出数据”，而是让用户快速形成口碑判断。

## 4. 统一视觉结论

### 4.1 当前前端与效果图的核心差距
核心差距不是功能缺失，而是：
1. 首屏信息量不足
2. 横向布局不足
3. summary 卡系统不够强
4. 图表参与度不够高
5. 业务提示 / 预警 / 建议模块不足
6. 页面更像“结果页”，而不是“工作台 / 看板”

### 4.2 优化方向结论
如果后续要做视觉升级，建议优先级为：

#### 第一优先级：首屏重排
- 提升首屏信息密度
- 增加 summary 卡
- 增加横向布局
- 把关键信息前置

#### 第二优先级：图表与业务可视化增强
- 增加分布图、进度条、趋势图
- 让图表成为页面核心而非附属

#### 第三优先级：辅助模块
- 提醒 / 预警
- 推荐下一步
- 快捷入口
- 空态 / 无权限态 / 延迟态的更产品化表达

### 4.3 一句话结论
这些效果图传递的核心不是“更花哨”，而是：

> 用更高的信息密度、更强的卡片化结构、更多图表与摘要模块，让页面在第一屏就形成业务判断。

## 7. P1 实施记录（2026-10-27）

### 7.1 后端契约增量（不改既有字段语义）

| 接口 | 新增 | 口径 |
|---|---|---|
| `GET /api/products` | `summary.{fullCoverage, withSales, withReview}` | 同一过滤条件下的 `FILTER` 计数 |
| `GET /api/products` | `breakdown.{state[], coverage[]}` | 两条 `GROUP BY`，缺桶补 0，`state` 按 0/1/2/3/5 固定顺序 |
| `GET /api/products/:spu/overview` | `header.metrics.{sales30dUsd, ratingAvg, skuCount, channelCount}` | 直接读 `pd_spu` 预聚合列，不额外查表 |

`breakdown` 与 `summary` 都是**全量口径、随筛选联动**：列表页的「状态分布」图不再用当前页 20 条数据画（那会是假图），符合「不自己造数据补空」的硬规则。`sales30dUsd` / `ratingAvg` 仍走 `commercial()`，无权限返回 `no_access` + `value: null`。

实测：`total 1067`、`summary {1067, 496, 35, 112, 76}`、`state 154/270/356/249/38`、`coverage 571/253/132/76/35`，两个分布求和均等于 1067；`?state=2&brand=Momcozy` → `total 288`、`state` 桶只剩 288。

### 7.2 页面重排

| 页面 | 结构 |
